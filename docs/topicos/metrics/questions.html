- [ ] Parar a aplicação após 5 minutos de inatividade. - [ ] Medir apenas o uso de memória do computador. - [x] Medir a latência (duração de tempo) e a frequência de execução de operações ou endpoints. - [ ] Registrar o relógio do sistema operacional para agendamentos cron. # Qual a diferença entre um Timer e um DistributionSummary? - [ ] O Timer só aceita números inteiros e o DistributionSummary aceita texto. - [x] O Timer é específico para grandezas de tempo (latência), enquanto o DistributionSummary mede valores escalares arbitrários (como tamanho de payloads em bytes). - [ ] Não há diferença, são sinônimos perfeitos. - [ ] DistributionSummary serve apenas para contagem de erros 500. # O que são tags dimensionais no Micrometer e qual sua vantagem? - [ ] São comentários que aparecem no código Java após a compilação. - [x] São pares chave/valor que enriquecem as métricas, permitindo filtrar e agregar dados por endpoint, método HTTP ou status. - [ ] São identificadores exclusivos de hardware exigidos pelo Linux. - [ ] São senhas de acesso aos relatórios do Prometheus. # Como o Prometheus coleta as métricas da aplicação Quarkus? - [ ] Porque o Micrometer só atualiza os dados à meia-noite. - [x] Porque as métricas são construídas de forma lazy e só aparecem após a primeira invocação ou registro do trecho instrumentado. - [ ] Porque o endpoint /q/metrics exige reinicialização do sistema operacional. - [ ] Porque é necessário recompilar o Quarkus em modo nativo. # Como a anotação @Timed ajuda a monitorar métodos de endpoints REST?
